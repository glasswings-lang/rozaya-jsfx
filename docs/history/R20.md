# R20 — history

**Budget: 200 lines**, like every file in `docs/history/`. Read this to find out
whether something has already been tried and killed. The rule itself lives in
`docs/suite-consistency-plan.md`, Part 2, "The four rules inside the order".

**Closed, and off the rules list, 2026-09-15.** Mostly built already: every rate in the
suite had the five-choice picker beside its value, and the retired sync shapes were gone as
working controls. What was built differs from the plan twice: the picker grew to five (R21),
and every pair was built value first (mode first came later, and is in the backlog). The
work still owed is one entry in `docs/backlog.md`. Nothing built for it except one fix.

## How it was closed, question by question

- **The three `Host ratio (retired)` controls** (Heartbeat, Rhythm Track, Stereo Phaser)
  were hidden and their code forced off -- hidden from the plugin window only. Rozaya uses
  the parameter list, where they still show. *"Yes. yes they should"* (come out).
- **Voice rates.** Polyrhythm and Shepard Tone voices read the one main picker. Claude
  proposed a picker per voice, used only in Independent and hidden otherwise. Rozaya: *"I
  use the p list. so good luck with that."*, then *"No this is way overspecked"*. Claude
  recorded that as keeping one shared unit; Rozaya: *"for god's sakes I made no decisions
  there. none."* Claude's example of a fraction (every 3 beats against 2 per beat) was not
  how Rozaya writes polyrhythms: *"no 0.5 anywhere. i don't even know where you came out with
  that"*. Rozaya's shape: *"Why not have the picker work like every other per-voice control,
  with the voice selecter at the top, taking its place and moving the rate unit just below
  it?"* In Drift each voice reads the shared Rate value in its own unit: *"I like your idea,
  and that's the point of the entire thing as it is."*
- **Phase offset, measured with `jsfx_run`:** seconds on BPM, Seconds and Hz, beats on the
  two beat units, whatever its name (`in rate mode units`) and its comment (BPM = beats, Hz
  = cycles) said. Rozaya: *"if I set a mode I'd expect that mode"*. An offset inside a
  repeating pulse wraps, so a whole pulse is inaudible. Percent was weighed (*"I don't
  know."*); Rozaya: *"phase offset should get its own unit picker with all voices as an
  option tbh, sidesteps the whole forced choic"*. Degrees out (*"Degrees doesn't make much
  sense to me"*). Hz in, though bigger means shorter: *"Yes, because you're capable of doing
  math I can't, at that stage"*; BPM and N per beat in (*"Yes"*); order lined up with the rate
  picker (*"Yeah"*).
- **Start delay, measured in seven plugins:** Seconds counts seconds, every other unit counts
  cycles. Tremolo and the Sweeping Filter DIVIDED by N on Every N beats (a leftover from
  when mode 3 was a multiplier): a delay of 2 at every 4 beats waited a quarter second.
  Fixed on request (*"Yes please."*), measured after, no saved instance affected. Dapple
  read, not measured: its bubbles were too quiet against the input to detect.
- **Shepard Tone's Voice selector.** The only record of Rozaya declining one is for Melody
  (*"melody phase deliberately lacks a voice selecter"*); an unquoted line had said Shepard
  "needed no selector". Rozaya: *"Yes. that'd make it a lot easier"*; the rate unit under it
  (*"Yeah, I think it should"*); *"Basically any per-voice control should"*.
- **Heartbeat's Breath cycle,** the one rate with no picker: *"Yes, yes it should"*. Rozaya
  first asked for below 0; reading showed a negative length duplicates `Breath HRV depth`'s
  existing reverse, which is also where Womb keeps its sign. *"0 should just 0 it out"*.
- **Transport with per-voice units.** A Shepard cycle is one tone crossing the whole octave
  window, and nothing marks it: *"Cycles doesn't have a meaning in shepard tone though?"* --
  so `{Seconds, Beats}` (*"Seconds and beats"*). Polyrhythm's Cycles counts each voice's own
  pulses, Start delay included: *"Yeah"*.
- **Permute swaps a voice's unit with its speed:** *"Absolutely yes"*.
- **Reverse drift offset.** A one-voice `Both — time` render did not show its purpose:
  *"this isn't representing, I think, why reverse drift is a thing."* Its commit did: it
  replaces two stacked tracks with mirrored, shifted drift palettes (the `diamonds` workflow),
  via `Both — permute` plus the offset. Its own unit picker: *"Yes"*.
- **Resonance Bank's `Drift period mode`** stays: *"that seems like more of a drift concern
  than a rate one"*.
- **Names:** *"They should yeah"* -- `<name> mode`, then `<name> value`.

**Found on the way, not R20:** Tensor's `shepard.RPP` is on no layout cleanly (open bug 4),
and every Polyrhythm render here began with a loud thump in the first 5 ms, not yet checked
in REAPER.

## Why the two dead shapes existed, so nobody re-derives them

Moved out of the plan 2026-09-09. R20 itself says what to build; this is the
record of the two shapes that were built first and thrown away.

**R11's sync block (Melody, Womb).** Its stated justification was that a plugin
syncing more than one thing independently cannot express two beat counts in one
rate value. **That is true and it is the wrong conclusion**, because you do not
use one rate value for two rates — you give the second rate its own pair.

The real constraint was narrower and is worth stating exactly, because it is a
missing control rather than a limitation: **Melody's `Pan base rate` (slider 21)
has no mode of its own.** Read `rate_to_cycle_seconds(pan_base_rate, rate_mode)`
at melody_phase.jsfx:1116 and :1492 — the pan is handed the SEQUENCER's
`rate_mode`. So there was nowhere to put Host x for the pan, and three sliders
were added to reach around the outside. One slider — a pan rate mode — does it
better, and untangles the pan from the sequencer's units as a side effect.

**Measured, and this is the number that ended the argument.** Across all 73
Melody Phase instances in the library, 27 have `Sync to host` ON, and **all 27
have the target set to `Rate value`. Not one points at the pan.** The capability
those three controls exist to provide has never been used, and it cost three
positions in the parameter list on every instance since it shipped.

**R13's "sync is not a unit" split.** Overturned by R13-revised on 2026-09-02 and
still dead. Host x IS a rate mode — it is one of the ways of saying what the
rate is.

**A rate's Drift and Ramp amounts are BPM in every mode, Host x included (2026-08-12).**
Rozaya, settling what a session had flip-flopped on: *"let drift and ramp have the literal
exact same flux as womb or heartbeat. Cause bpm is bpm, fuck being gridlocked for something
like that, fractions of a beat only make sense when you're playing with the grid and + or -
20 in beats is just that added or subtracted from project bpm when host sync is the mode
anyway."* The plugin converts: in Host x a BPM amount D adds `D / tempo` to the multiplier
(`host_bpm_delta()`). A multiplier delta was argued twice and killed: a 0.1 step is BPM's
grain, a 10% wander as a multiplier. Under R26 this is what `Target default` means for a rate.
Moved from `docs/planned-features.md` on 2026-09-13.

## R20 — THE RATE BLOCK, settled: a rate value and a rate mode, adjacent, everywhere (2026-09-04)

**Supersedes R11 entirely and completes R13-revised.** Decided with Rozaya on
2026-09-04 after five separate sessions had each reached for a different shape.
If you are reading the suite for "how does tempo sync work here", stop at this
section — everything below it is history and two of the shapes it describes are
dead.

## The rule, in full

**Every rate in a plugin carries exactly two controls, adjacent, MODE FIRST:**

```
<Name> rate mode         {BPM, Seconds, Hz, Host x}   -- ALWAYS these four, ALWAYS this order
<Name> rate value        free number
```

Rozaya, 2026-09-14: *"every thing with a mode gets the mode before the value.
everything. I don't care what it is."*

The mode says the unit, so a rate's name lists no units. The exception is a name
that explains something its mode can't: the breath rate in Breath Generator and
Womb says `per minute, or beats per breath`, and Rozaya said to leave both.

- **In Host x, the rate value means EVERY N BEATS.** One cycle takes N beats of
  the project. Bigger is slower. It is a free number, so `0.333333` — every
  three beats — is as reachable as `4`.
- **The mode list is identical everywhere.** Same four entries, same order, in
  every plugin, for every rate. This is the whole point: the suite is navigated
  by arrowing the parameter list one control at a time, so position 3 must not
  mean Hz on one control and BPM on the one under it.
- **A plugin with two rates has two of these pairs**, each complete and
  self-contained. The pan gets its own rate value and its own rate mode. It does
  not borrow the main rate's mode, and nothing points across at it.

**What this replaces — each of these has been built at least once, and each is retired for good:**

- No `Sync to host` switch. Host x is a rate mode; a second switch is a second
  way to say the same thing.
- No `Host sync target` selector. Each rate carries its own sync.
- No separate `Every N beats` slider. The rate value IS that number in Host x.
- No `Host ratio` picker, or any control whose job is to write a value into
  another control. All seven were retired 2026-09-04 and they stay retired.
- No multiplier, anywhere, in any mode.

**Why the two dead shapes existed**, so nobody re-derives them, is in
`docs/history/R20.md`.

## The near-miss this rule must not repeat

**BEFORE DELETING ANY CONTROL THIS RULE RETIRES, OPEN THE BLOCK AND READ IT.**
On 2026-09-04 a plan document described Womb's `Every N beats` as a leftover and
it is not — it is half of a working pair. Rozaya: *"host x is the rate mode.
every N beats is getting the multiplier out of there. neither of them work
alone."* R20 does retire it, but **by moving its number into the rate value,
with a migration**, which is a different operation from deleting it. A retired
`Host ratio` picker writes one slider and does nothing else; a working half of a
pair does something the other half depends on. Those look identical from the
slider list and completely different from inside.
