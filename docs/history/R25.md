# R25 — a control behind a selector says which kind it is

## How it came up (2026-09-12)

Designing eight ramps, I asked whether a later ramp's start should count from the end of
the one before it "per control or once per ramp", and mentioned in passing that Ramp start
delay is per target today. Rozaya: *"I was under the impression that start delay was
global affecting all ramp controls. So what the hell is going on here?"*

Read in code, all 17 plugins with a Ramp: Ramp start delay is banked per target
(`speed_ramp_delay_mem[target]`; Resonance Bank per band), and the plugin pages say
"per-target". But the slider appears once in the list and its label says only
`Ramp start delay (in ramp time units)`, so by screen reader it reads as one setting for
the whole plugin. Most Drift and Ramp controls switch with their target without saying so;
a few (Drift period unit, Ramp time unit, Ramp engage) are shared, also without saying so.
The only hint anywhere was "units match target" on the amounts.

Rozaya: *"It switches. when. you change. the target? But it says ramp start delay ... if
it's gonna do that, can't it at least say that's what it's doing?"*

In the same exchange I had to correct two things I had told Rozaya without checking: that
a ramp's start delay counts from the start of the song (it counts from pressing play, only
while engaged), and the wording of a design choice built on that.

## What was decided

Wording offered and accepted ("anything would do at this point"): `(per target)`,
`(all targets)`, and `(per slot and target)` for Passage. Applied to Drift and Ramp in every
plugin at once, because a rename moves no saved value.

## Shapes not taken

- Leaving it to the plugin pages: Rozaya does not read them, and a label is where the
  meaning has to live (`feedback-no-docs-they-must-remember`).
- Waiting for the eight-ramps build to rename everything once: several sessions away, and
  the controls would go on misdescribing themselves until then.

## Flipped 2026-09-15 — mark only what is shared

Rozaya, on the Morpher's `Layer level (dB, per layer, -60 = off)`: *"Morfer's thing is
*cluttery* to read back, and is why I've bitched out claude for doing it that way lol ...
maybe instead of cluttering up the majority of controls, we can just mark the ones that
effect a whole of a plugin's output? ... that way non-global things can safely be assumed
to be non-global because we've not put that mark there. Less to read, as well."*

The count says it plainly: 241 controls carried a `per <thing>` mark and 58 carried the
shared mark. **262 slider names and 42 page headings lost theirs.** Offered `(global)`
against naming what the "all" is, Rozaya: *"all voices/segments/whatever, I think that one's
better"* -- so the 58 already reading `(all targets)` needed no change, and `(global)` is
not used: it would be wrong on a drift control that is shared across targets but touches
nothing else in the plugin.

## Where the flip does not work on its own, and the prefix that fixes it

**A selector's block has to END somewhere**, or an unmarked control after it lies. On
Polyrhythm that bites hard: fifteen controls belong to the Voice picker and the
twenty-nine after it do not, so marking the shared ones would have ADDED reading.

Rozaya: *"I think voice prefixing would help there, because you can first-letter nav
through the p list."* So the group's word goes at the FRONT, and that is not decoration --
it is how the group is reached, and it ends the block without marking anything after it.

- **Prefixed:** Polyrhythm's fifteen (`Voice gain`), Sweep Dwell's eight (`Segment
  length`), and the five-control pitch block on Breath Gen, Heartbeat and Rhythm Track
  (`Pitch note name`). Rozaya, asked because the pitch block is settled: *"nah, do the
  renames. the nice part is that renames don't cost anything."*
- **Already prefixed, so nothing to do:** the Morpher's `Layer *` and `Capture *` blocks.
  Deleting its `(per layer)` was the whole fix -- the front word was always there.
- **Marked instead, because the per-X controls are the majority:** Resonance Bank, where
  thirteen are per band and only `Wet/dry mix` and `Output volume` are not. Both read
  straight from their sliders, never through a band bank.

## Passage, closed the same day

The caution about measuring was over-careful. Passage declares which controls belong to a
slot in THREE independent places -- the `ps_all` / `ps_all_key` calls (27 + 14), the
`ps_adopt` mirror, and the write-back when the picker moves -- and all three agree exactly
with the 41 that carried the `per slot` label before the strip. Zero discrepancies, so the
list is the code's, not a reading of it.

Eleven controls were shared and said nothing; they now say `(all slots)`. Left alone:
`Capture now` (it acts on whatever the picker is on), `Morph (% across captured slots)`
(its own name already spans them), and the whole drift and ramp block. Rozaya, asked
whether its shared controls should read `(all slots and targets)` rather than `(all
targets)`: *"I feel like once you're drifting or ramping something, you don't need that
kind of redundency."*

**On untangling Passage itself:** its slot table is positional -- a row reads
`ps_last[12] = slider15`, so nothing tells you what it is without counting. Naming those
rows would be hours of work and real risk for no change in sound. Asked how bad it would
be, the answer is: bad enough not to, and unnecessary, because the table already answers
every question anyone has asked of it.

## Re-measured 2026-09-15, because the first measurement was taken in a rush

Rozaya: *"Are those verified though? this was during the time that thing was being crammed
in and crammed in."* Fair -- the 09-12 labels came from one live probe during a crowded
run, and nothing since could re-check them without REAPER.

`tools/r25_scope_verify.py` now re-measures them in the runner: picker to option 1, set the
control off its default, step a block, picker back to option 0, read it back. **All 19
plugins, every `(all targets)` claim, 0 mismatches**, with `Drift period` measured beside
each as the control case and coming back per-target every time (so the method is not just
agreeing with itself). Resonance Bank's `Drift period mode` measured per target, which is
the odd one out the backlog entry describes -- the measurement found it, not a label.
